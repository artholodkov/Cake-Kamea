Вердикт по платформе

Shopify подходит. Shopify Plus ($2300/мес) и кастомный чекаут — НЕ нужны.

Развеиваем главный миф. $2300/мес — это тариф Shopify Plus, и он нужен только чтобы кастомизировать саму страницу чекаута (свои поля, свой дизайн оплаты). Конструктор торта чекаут не трогает вообще — это обычная страница ДО корзины: клиент собирает торт, жмёт «в корзину», дальше идёт стандартный шопифаевский чекаут. Значит Plus не требуется — хватит обычного плана (Basic / Shopify, ~$39–105/мес).

Конструктор реализуется без единой платной подписки. Раз «одна строка в корзине не принципиальна» — допы кладутся отдельными позициями через штатный Cart AJAX API, персонализация уходит в line item properties. Ни приложения-конфигуратора, ни Shopify Functions, ни Plus. Платишь один раз за разработку — дальше 0 ₽/мес.

Настоящая сложность проекта — не конструктор, а логика «наличие / срок изготовления / доставка» (смешанная корзина) и организационное подключение платёжного шлюза. Им посвящены отдельные разделы ниже.

Конструктор торта — техрешение

Ключевой блок · решено

Отдельная страница, 0 подписок, без Plus

Кастом, но дёшево

Конструктор — отдельная страница только для «конструируемых» тортов (голые торты + торты, у которых разрешён декор). Начинку в конструкторе не выбирают. Собирается на штатных возможностях темы.

Механика

  • Базовый торт — товар, вес = варианты (у каждого своя цена).
  • Всё платное (венок, печатная надпись, лента, упаковка, свечи, топпер) — отдельные товары-допы (скрытая коллекция, только для конструктора).
  • Всё бесплатное (текст, форма таблички, значение цифры) — line item properties, уезжают в заказ, менеджер их видит.
  • Живая цена на странице = сумма выбранного (считает JS).
  • В корзину всё летит одним запросом Cart AJAX API. Общий признак _Сборка связывает позиции — в кастомном drawer'е группируем их визуально под тортом.

fetch('/cart/add.js', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ items: [
    { id: cakeVariantId, quantity: 1, properties: { 'Надпись': 'С днём рождения', '_Сборка': 'A17' } },
    { id: wreathVariantId, quantity: 1, properties: { '_Сборка': 'A17' } },
    { id: packVariantId,   quantity: 1, properties: { '_Сборка': 'A17' } },
    { id: candleVariantId, quantity: 1, properties: { 'Цифра': '5', '_Сборка': 'A17' } },
    { id: topperVariantId, quantity: 1, properties: { '_Сборка': 'A17' } }
  ]})
})

Почему НЕ нужны Functions и Plus

Cart AJAX API и line item properties — это ядро Shopify на любом плане. Functions для этой схемы не нужны вообще. И сам миф «Functions = только Plus» неверен:

Тип Shopify FunctionПланНужен нам?
Discounts (скидки)Все планынет
Cart Transform (бандлы, слить в 1 строку)Все планынет
Cart / Checkout ValidationВсе планыопц.
Payment customizationТолько Plusнет
Delivery customizationТолько Plusнет
Даже «одна строка с суммарной ценой» (если захочется позже) — это Cart Transform, а он работает на обычном плане (на нём же построено бесплатное 1st-party приложение Shopify Bundles). Plus упирается только в кастомизацию самого чекаута, которая проекту не нужна.

Наличие, сроки и доставка — главный узел

Требует продумывания · бизнес-логика

Смешанная корзина: наличие vs «под заказ»

Главная сложность

Товары делятся на два типа, и это ядро всей логики заказа:

В наличии
Готовые торты / пирожные / десерты — можно привезти день в день.
Под заказ
Торты с декором / из конструктора — срок изготовления минимум 1–2 дня, день в день нельзя.

Согласованное правило

  • Не отказываем клиенту — заказ можно оформить всегда, просто корректно сообщаем срок.
  • Дата доставки — по самому долгому товару в корзине. Весь заказ едет одной доставкой (её нельзя дробить), когда готово всё.
  • В конструкторе сразу плашка: «Торт с декором готовится минимум 1–2 дня, доставка день-в-день недоступна».
  • В корзине — нотификация «В заказе есть товары под заказ, ближайшая доставка — [дата]» только если такой товар в корзине есть. Если нет — нотификации нет, доступна день-в-день.

Как на Shopify (без приложений)

Тип и срок
Метафилд у товара: под заказ = да/нет и срок, дней. Ставится вручную у тортов с декором.
Наличие
Штатный inventory Shopify. «Нет на складе, но можно под заказ» → разрешить продажу при нуле остатка + метка срока.
Плашки/нотификация
Логика в теме (Liquid + JS): читаем метафилды позиций, показываем предупреждение и вычисляем ближайшую дату. Всё на обычном плане.

Где выбирать дату доставки — важный нюанс

Дата на самой странице чекаута требует приложения или Plus. Чтобы остаться на 0 подписок, есть два бесплатных пути:

  • Дату/слот выбираем в корзине (штатные cart attributes) → значение уезжает в заказ. Бесплатно, и туда же ложится нотификация про сроки.
  • Либо дату финально подтверждает менеджер на звонке (он и так звонит уточнить адрес и прислать QR) — тогда на сайте показываем только ближайшую доступную дату, поле не обязательно.

Слоты времени — «от доступности Lalamove», поэтому жёсткий график можно не зашивать: диапазоны подтверждает менеджер.

Предварительная оценка объёма

Ориентир в человеко-днях. Разработка с AI (Claude/Codex) ускоряет верстку и JS, но интеграции (шлюз, Lalamove) и тесты логики сроков кодом не ускоряются. Не заменяет ТЗ — рамка для планирования.

Что решить/сделать до старта

Оформить платёжный шлюз. Начать подключение Opn (Omise) или 2C2P — там KYC и сроки, это стартовать первым.
Финализировать правило сроков доставки. Подтверждено: дата по самому долгому товару, не отказываем, нотификация в корзине/конструкторе. Осталось решить, где собираем дату — в корзине или у менеджера.
Разметить товары метафилдами. «под заказ», «срок дней», «можно кастомить», аллергены, состав, персоны.
Собрать товары-допы для конструктора. Венок, печатная надпись, лента, упаковка, свечи, цифры, топпер — с ценами; скрытая коллекция.
Определить минимальную сумму заказа. Значение пока не задано.
Токены и состояния в макете. Сетка, брейкпоинты, радиусы/тени, состояния компонентов (hover/focus/disabled/error).
Согласовать объём MVP под срок. Что входит в первые 2–3 недели, что — во вторую волну.

Остаточные открытые вопросы

Дата доставки. Собираем в корзине (поле выбора) или показываем только ближайшую дату, а точную согласует менеджер на звонке?
Минимальная сумма заказа. Какое значение и одинаковое ли для самовывоза и доставки?
Форма таблички в конструкторе. Влияет на цену или бесплатная опция?
Аналитика и чат. Пиксели (Meta/TikTok/Google), WhatsApp-виджет — в апселл; определить, что ставим на старте.
Объём MVP. Финальный список того, что запускаем в первые 2–3 недели.
